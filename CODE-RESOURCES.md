# Executable resources

Native definitions retain the classic resource type and ID. System currently
bundles independently linked WDEF 0, CDEF 0 (Buttons, Checkboxes and Radio
Buttons), CDEF 1 (Scroll Bar), CDEF -32760 (Progress Bar), CDEF -32759 (Static
Text), and MDEF 0. Managers
resolve application resources first, then System resources, and cache entries
by type, ID and origin. Each definition owns its drawing, geometry and behavior. The placement/PIC
contract applies to every native executable definition family, including WDEF,
CDEF, MDEF, LDEF and future registered families; none gets a fixed per-family
manifest address.

System's link range comes from the checked platform virtual layout. Every
independently loadable definition, driver and extension uses the same platform-
derived link origin/capacity, not a manifest-selected address. Packaging derives
its actual page-rounded memory span from ELF, including BSS. System chooses the
actual runtime destination; current definitions allocate top-down from their
resident arena and modules allocate from their separate arena. These mappings
are still shared supervisor mappings, and physical unloading remains future work.
Application placement fields remain transitional until private process spaces.

## Building a native definition

`definitions/wdef`, `definitions/buttons`, `definitions/scrollbar`,
`definitions/progress-bar`, `definitions/static-text` and `definitions/mdef`
have their own manifests, linker
scripts generated by `mac-build`, and C entry points:

```text
unsafe extern "C" fn(*mut mac_abi::DefinitionCall) -> i64
```

The System manifest embeds them with `format: "native_code"` and only the Cargo
binary name in `artifact`. Neither the definition manifest nor its embedding
payload supplies `load_base`/`load_limit`; those keys are rejected for System
and code-resource build manifests. Artifacts resolve beside the actual input ELF in
this build's target/profile directory. Build-script dependency tracking uses the
same selected directory; private checks never read a regular desktop artifact.
Each payload is a 40-byte `RVN1` descriptor
([FORMAT.md](FORMAT.md)) with role 3, followed by the minimal RV64 segment stream
and its mandatory RLOC table. Complete
debug executables stay outside the resource fork. The loader validates both
descriptor and segment stream, rejects relocation slots in executable bytes,
copies segments, clears BSS and publishes instructions to all admitted CPUs.

Native Cargo dependencies are built with `relocation-model=pic`; conflicting
codegen overrides are refused. Executable instructions must remain position
independent. RLOC adjusts internal absolute data/GOT pointers before publication;
PIC does not eliminate Rust vtables and other address-bearing data. Paired
internal ADD32/SUB32 jump-table differences remain unchanged when both endpoints
move together. Unsupported, external and executable-slot relocations fail before
any runtime writes. Boot ROM's pre-data-init assembly uses explicit PC-relative
label addresses so its startup never depends on an uninitialized RAM GOT.

`DefinitionCall` carries a version/size header, resource type and ID, variation,
message, parameter, object pointer, optional drawing surface and a loader-supplied `TrapGate`. These are
native RV64 layouts. Each manager defines its object type and message contract.
The WDEF uses `WindowDefinitionState`; the CDEF uses `ControlDefinitionState`.
They are not classic WindowRecord/ControlRecord layouts. Each definition owns
its behavior in `src/main.rs`, including its entry point. WDEF supplies frame,
button and grow-icon drawing, geometry, zoom-box bounds and hit testing. CDEF
owns its button behavior. They use `toolbox-quickdraw` bindings for OS graphics
primitives and font services; neither embeds System's rasterizer or font strikes.
Host tests and the reference renderer reuse the same resource source files. Definition callbacks
must preserve the supplied clip and must not recursively pump application events.

## Automatic translation boundary

[`mac-formats::code`](crates/mac-formats/src/code.rs) classifies common executable
resource families and passes the calling convention to `CodeTranslator`:

| Family | Convention |
| --- | --- |
| WDEF, CDEF, MDEF, MBDF, LDEF | Window, control, menu, menu-bar and list definitions |
| CODE | Segment; ID 0 is a jump table |
| INIT, DRVR, FKEY, cdev | Initializer, driver, function-key and control panel |
| PACK, proc, ptch | Package, procedure and patch |
| dcmp, ADBS | Resource decompressor and ADB driver |

The registry can declare additional executable types for custom managers or
components. Data resources such as WIND, CNTL, MENU, DITL and thng do not trigger
translation just because they refer to code.

Every executable-resource preparation goes through `CodeRegistry::prepare`.
A native `RVN1` envelope is validated directly. Other bytes automatically invoke
the translator with the resource, origin and calling-convention profile; the
backend must return a native envelope with the required ABI adapter. CODE 0
tables, driver headers and package dispatch tables require structural handling,
not instruction decoding of every byte.

**There is no 68k translator yet.** The installed `NoTranslator` backend returns
an explicit translation-required error (`TRANSLATION_REQUIRED` at the System
service boundary). Unit tests verify automatic routing for every registered
family with a test backend. The standard WDEF, both CDEFs and MDEF have live manager execution; additional
resource families retain their declared translation contracts. ResEdit recognizes
all registered families and displays native envelope disassembly plus NABI/RLOC
metadata, while untranslated payloads remain inspectable as hex.

## Planned ResEdit editor resources

ResEdit's [extension workstream](docs/RESEDIT.md#planned-resource-editor-extension-api)
will register executable `RSSC` resources and a ResEdit-specific calling
convention. Each native editor will use the existing compact code-resource
format and relocation path, with its own versioned host interface. This is
planned, not an implemented registry family or loader contract. Merely reading
an `RSSC` resource must never prepare or execute it; installed editor discovery
is separate from inspecting a target file. Original 68k `RSSC` compatibility
requires the translator and original ResEdit API adapter.

## Planned System extensions and control panels

[The System-extension plan](docs/SYSTEM-EXTENSIONS.md) defines a future native
`INIT` module calling convention and resource metadata for kernel services.
It reuses compact segments/RLOC rather than ELF or app-entry dispatch. Original
`INIT`/`cdev` classification above does not implement boot discovery, kernel
registration or legacy panel hosting. Those require their own loader/lifecycle
and compatibility gates; runtime resource inspection must remain non-executing.

## Planned native driver contract metadata

[P14](docs/DRIVERS.md) requires a native DRVR package/code resource plus a
build-generated DABI metadata resource describing driver API, target, required
kernel services, entry/request layouts and device-class contracts. The loader
rejects absent/incompatible metadata before entry. Exact layouts remain future
FORMAT.md work; existing compact code envelopes and legacy DRVR calling profiles
do not themselves implement native driver loading. DABI is data for inspection,
including a future resource-based ResEdit viewer, not another executable family.

## Standard WDEF reconstruction

[Retained analysis](../analysis/wdef-standard.md) records the System 7.6.1 source
hash, extracted resource hash, dispatch offsets and observed geometry. The Rust
handler supports variations 0, 1, 2, 3, 4, 5, 8 and 12 and messages 0–6.
Window Manager owns z-order, activation, tracking and exposure; WDEF owns
variant-specific structure, decoration and hit parts. Drawing uses the original
Chicago 12 bitmap strike and the measured default reference-device color palette.
All 29 retained original-Mac cases match exactly across 2,239,315 RGB pixels,
including all eight variations, inactive/pressed states and clipped titles.
The production RV64 window frame is checked separately against this renderer.
See [the Window Manager notes](system/src/toolbox/windows/README.md) for reproduction and
the limits of the verified device profile. Custom palettes, alternate fonts,
rounded WDEF 1 and the original 68k ABI remain future work. No Apple executable
bytes are embedded in the native definitions; the original font assets are data.
