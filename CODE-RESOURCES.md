# Executable resources

Native definitions retain the classic resource type and ID. System's resource
fork currently contains independently linked **WDEF 0** and **CDEF 0**; Finder
does not implement their frame/button drawing. System resolves application
resources first, then System resources, caches each loaded entry by type, ID
and origin, and rejects conflicting load reservations.

The current fixed ranges are:

| Image | Reservation |
| --- | --- |
| System | `0x80200000..0x81000000` |
| Finder | `0x81000000..0x82000000` |
| WDEF 0 | `0x82000000..0x82100000` |
| CDEF 0 | `0x82100000..0x82200000` |

Other executable resources may use non-overlapping reservations in
`0x82000000..0x85000000`. Relocation and unloading are future work.

## Building a native definition

`definitions/wdef` and `definitions/cdef` have their own manifests, linker
scripts generated by `mac-build`, and C entry points:

```text
unsafe extern "C" fn(*mut mac_abi::DefinitionCall) -> i64
```

The System manifest embeds them with `format: "native_code"`, `path`,
`load_base` and `load_limit`. Each payload is a 32-byte `RVN1` descriptor
([FORMAT.md](FORMAT.md)) with role 3, followed by a stripped RV64 ELF. Complete
debug executables stay outside the resource fork. The loader validates both
descriptor and ELF, copies segments, clears BSS, and executes `fence.i`.

`DefinitionCall` carries a version/size header, resource type and ID, variation,
message, parameter, object pointer, optional drawing surface and a loader-supplied `TrapGate`. These are
native RV64 layouts. Each manager defines its object type and message contract.
The WDEF uses `WindowDefinitionState`; the CDEF uses `ControlDefinitionState`.
They are not classic WindowRecord/ControlRecord layouts. Each definition owns
its behavior in `src/main.rs`, including its entry point. WDEF supplies frame,
button and grow-icon drawing, geometry, zoom-box bounds and hit testing. CDEF
owns its button behavior. They use `toolbox-quickdraw` bindings for OS graphics
primitives and font services; neither embeds System's rasterizer or font strikes.
Host tests and the reference renderer reuse the same resource source files. Definition callbacks
must preserve the supplied clip and must not recursively pump application events.

## Automatic translation boundary

[`mac-formats::code`](crates/mac-formats/src/code.rs) classifies common executable
resource families and passes the calling convention to `CodeTranslator`:

| Family | Convention |
| --- | --- |
| WDEF, CDEF, MDEF, MBDF, LDEF | Window, control, menu, menu-bar and list definitions |
| CODE | Segment; ID 0 is a jump table |
| INIT, DRVR, FKEY, cdev | Initializer, driver, function-key and control panel |
| PACK, proc, ptch | Package, procedure and patch |
| dcmp, ADBS | Resource decompressor and ADB driver |

The registry can declare additional executable types for custom managers or
components. Data resources such as WIND, CNTL, MENU, DITL and thng do not trigger
translation just because they refer to code.

Every executable-resource preparation goes through `CodeRegistry::prepare`.
A native `RVN1` envelope is validated directly. Other bytes automatically invoke
the translator with the resource, origin and calling-convention profile; the
backend must return a native envelope with the required ABI adapter. CODE 0
tables, driver headers and package dispatch tables require structural handling,
not instruction decoding of every byte.

**There is no 68k translator yet.** The installed `NoTranslator` backend returns
an explicit translation-required error (`TRANSLATION_REQUIRED` at the System
service boundary). Unit tests verify automatic routing for every registered
family with a test backend. Only the native WDEF and button CDEF have live
manager execution in this milestone; the other managers remain future work.

## Standard WDEF reconstruction

[Retained analysis](../analysis/wdef-standard.md) records the System 7.6.1 source
hash, extracted resource hash, dispatch offsets and observed geometry. The Rust
handler supports variations 0, 1, 2, 3, 4, 5, 8 and 12 and messages 0–6.
Window Manager owns z-order, activation, tracking and exposure; WDEF owns
variant-specific structure, decoration and hit parts. Drawing uses the original
Chicago 12 bitmap strike and the measured default reference-device color palette.
All 29 retained original-Mac cases match exactly across 2,239,315 RGB pixels,
including all eight variations, inactive/pressed states and clipped titles.
The production RV64 window frame is checked separately against this renderer.
See [the Window Manager notes](system/src/toolbox/windows/README.md) for reproduction and
the limits of the verified device profile. Custom palettes, alternate fonts,
rounded WDEF 1 and the original 68k ABI remain future work. No Apple executable
bytes are embedded in the native definitions; the original font assets are data.
