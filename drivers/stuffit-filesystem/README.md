# StuffIt Filesystem

Native `DRVR` + `DABI` package installed in `System Folder/Drivers`. It offers
FSYS v4 with `SOURCE_FILE` and consumes resident FORK v1 capabilities. System
owns mounted-volume/open/source/request IDs and application access checks.
The driver stores only those supplied tokens and immutable archive catalog IDs.

The package's `FASS 0` resource registers `SIT!`/`SITD`/`SIT2`/`SIT5` document codes, the mount
action, and its own local icon family 128. The separate `File Types`
preference classifies untyped `.sit` names. The document/zipper artwork has independent 16/32 pixel color and
monochrome variants, generated by `scripts/build_stuffit_icon.py`. System caches
the decoded family; Finder and file dialogs use the generic default-icon service.
Removing the package before boot removes its open action and icon. Live code
is pinned until reboot; deleting a loaded package does not hot-unload it.

Archives can live on HFS-B or provider-backed writable/read-only host exports.
The resident source adapter owns deferred acquisition, positional reads and
acknowledged Close. The provider admits up to 32 independently owned requests,
so an archive may read its backing fork from another volume mounted by the same
package. Each open decoder remains exclusive, and mount slots/publication storage
are reserved before pending I/O. Serialized providers remain explicitly refused
for self-backed mounts; no callback/event loop is recursively pumped.

`mac-sit` owns classic revisions 1/2 and StuffIt 5 headers, CRCs and
stored/RLE90/LZW/Huffman/LZ-Huffman (13)/Arsenic expansion. Filesystem/version information reflects
the archive container version (1, 2 or 5), independently of the FSYS contract. See [format evidence and limits](../../docs/STUFFIT-CLASSIC.md).
The driver adds NFC names and cached Unicode folding using the same pinned
name machinery as HFS-B. Ambiguous sibling names fail mounting rather than
silently hiding an entry. Native path-invalid names fail explicitly.

Catalog/lookup/scan use the mount-time cache without reading fork payloads.
Metadata preserves file type/creator/flags and both fork lengths. Version-5
Finder information, lock state, comments and directory timestamps are projected
through the native metadata contract. Classic 1.5.1's unspecified nested-folder
fields inherit source-file timestamps; revision-2/5 folders retain their dates. The mounted root uses the actual archive name/dates
supplied by System, rather than guessing a path from a source capability.

Reads retain a bounded decoder per open mark, reuse it for sequential/forward
reads, and restart when seeking backwards or switching forks. A callback does
one source operation or one bounded decode step, with no guard held across the
lower call. Requests own all pending input/output; short reads and cancellation
remain owned until acknowledgement. End-of-fork reads verify length and CRC
before returning, including a final read that exactly fills the caller buffer.
Earlier partial reads are provisional until that verification; copy-out must
abort publication if a later read fails.

The admitted module has a fixed 4 MiB heap, 16 mounts and 16 open marks; catalog
limits are 4,096 nodes / 64 levels, subject to that heap budget. Every allocation
uses a fallible path. Budget exhaustion returns `NoMemory`, without publishing
a partial mount. No operation buffers a whole fork.

Volumes advertise read-only and reject every mutation. Refresh/watch targets
remain valid for immutable volumes. Catalogs can show encrypted/unsupported
entries; opening them returns an informative typed archive failure, never empty data.

Host module tests exercise fresh callback buffers, deliberately short deferred
reads, seek/EOF, both forks, corruption, read-only mutations, cancellation and
invalid-ticket handling. Native public-SDK acceptance lives in
`crates/mac-toolbox/tests/stuffit.rs`; its capture transport uses private media.


Host Arsenic tests, seven private optimized guest SDK/Finder gates and the
private real archive verifier pass for classic revisions 1/2 and StuffIt 5 with
stored/RLE90/LZW/Huffman/Arsenic. The actual SuperPaint archive opens through
Finder, and public SDK reads verify all nine forks from both host export modes.
Native acceptance now also covers same-provider nested archive mounting and
recursive two-fork copies to HFS-B and writable host volumes. Physical Finder
checks exercise readonly rejection, failure/dismiss/retry and volume-to-Trash
unmount with an unchanged archive digest. Unsupported methods/encryption remain
explicit, informative failures; support is the documented codec set, not every
StuffIt family. See [the milestone record](../../docs/TRANSFER-MILESTONE.md).

Method-13 acceptance additionally covers all five standard codebooks, shared and
separate dynamic tables, an independent writer, full 64 KiB history wrapping and
maximum-distance references. Public-SDK checks verify both forks through the
installed driver, malformed-data/checksum messages, unaffected-fork recovery and
immediate source release. Both writable/read-only host sources and real Finder
opens are exercised. Ten driver callback tests cover the current codec set,
including cancellation while waiting for method-13 source bytes.
