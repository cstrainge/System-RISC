# Native definition resources

Definitions retain their own relocatable implementation in code resources.
The resident loader uses the shared executable-resource registry, including its
ID-sensitive calling conventions; it does not maintain another WDEF/CDEF/MDEF
allowlist. Non-native code still requests the unimplemented 68k translator and
returns the typed translation-required refusal. No ELF is stored in a resource.

## Source and physical ownership

DDEF/DSTA are canonical registered objects with generation-checked completion
keys. The record owns its original source read or sealed System resource proof,
execution exclusion, placement reservation and physical mapping. Existing
objects retain a private completion reference; neither an address nor a copied
resource ID can replace that authority. Global cache rows are only an index.

Initialized segments and BSS occupy actual buddy-backed pages. The original
Process or Module Kernel account pays for its definition payload; genuine System
resources use a distinct refundable ordinary-System physical receipt. This is
separate from fixed System heap occupancy and permanent Foundation attribution.
The public memory summary exposes tracked_ordinary_system_physical_bytes; it is
partial attribution of these leases, not a new quota or whole-machine sum.
Pages are cleared before copying and relocation. Final segment mappings retain
RX/R/RW permissions and sparse holes; the broad identity-mapped definition arena
is removed. Reservations still use the checked platform's definition VA range.

Source lookup ends before physical preparation and monitor waits. Only the exact
owned source authority and decoded NativeCode survive that boundary. A canonical
record reserves its range before any PTE effect and exposes an entry only after
actual publication. Concurrent preparation or uncertain publication retains the
original record and typed cause rather than installing another incarnation.

## Native call staging

Window, managed control, scrollbox and offscreen control requests validate their
request shape and genuine owner/object admission before cold preparation. Pure
standard-control validation uses the definition binding's same family codecs.
A cold native request leaves Desktop, prepares its selected code, then re-enters
and revalidates before object mutation. A changed admission refuses typed; it
does not spin or replay completed effects. Warm bound controls/scrollboxes use
the actual object's retained callable, without a catalog lookup or tracking scan
in the outer staging turn. Creation/configuration still perform their required
authoritative checks.

Non-core alerts decode ALRT/DITL once into an owned alert, validate admission and
button state, then prepare the selected app/System definitions outside Desktop.
The final commit revalidates owner and modal availability and consumes that same
alert. Protected core UI selects authentic System resources and uses preadmitted
defaults. There is no fallback to another source on a cold or stopped-source
refusal. Existing definition-author callbacks and port/object borrowing still
have their separate guarded execution path; this stage does not move them.

## Retirement and failure

Ordinary invocation refuses a stopped or closing source. Only Window Manager's
original invalidate-first ticket lookup creates the nonconstructible Dispose
permit. It borrows that exact ticket and invokes its retained WDEF; a wire
Dispose message grants no exception. Source and execution remain pinned through
the call. This permits actual owned-window disposal before source teardown.

The owner walk marks the definition closing and requests retirement. Its unique
ticket remains pending. Existing guard-free maintenance claims the actual
canonical record and execution exclusion, revalidates quiescence, removes PTEs
and obtains the real translation acknowledgment. Only afterward can the backing
and its original receipts be released and the walk finish. Desktop and registry
metadata guards do not span that physical retirement. Real reader/preparation
release and monitor progress provide wakeups; input and frames are not retries.
An uncertain transition retains the original mapping/source/range/ticket.

A foreign Process window currently holds only a completion reference to a
Module-owned definition. If that Module closes first, the later window Dispose
can be refused and quarantined. Safe refusal is not successful cross-domain
unload. A genuine bound-object dependency/unload contract remains required for
that case; this stage does not claim it. Arbitrary privileged-fault containment
also remains the unproven M-D04 gate.

## Bounded native observations — 2026-11-01

An optimized release/LTO RV64 image ran privately in four-CPU, 8 GiB, 800x600 QEMU
with event/TextEdit tracing disabled. System resource SHA-256 was
`a59df1a9dedd24d2b0598c281687f96f11907cfaed1a1b27bd2b3d787add50f8`,
System ELF was
`e11787fa468ab92ba6c023d80e3d69c4c44d551d16172d4e9d051a8f78e4267f`,
and ROM was
`5348bb19cbfe5c0820504278b997ba3ae183c5206e46a51dd6f388500df3f12b`.
Both Cargo freshness settings and actual content fingerprint records were
checked; the System package was rebuilt explicitly for generated inputs.

The unchanged installed Res Edit ELF was packaged normally with app-owned
WDEF/CDEF overrides. Actual launch admitted ten new nonidentity definition
pages with matching physical/protection views in both permanent roots and no
W+X leaves. Actual quit/account closure removed all those pages; a fresh
incarnation launched and quit again, followed by input. Paused read-only PTE
samples cost approximately125–127 ms of host time each and perturb execution.
They establish these sampled mappings, not latency or private-root coverage.

Malformed and 68k-shaped overrides separately retained their actual loader
causes and BAD_ARGUMENT/TRANSLATION_REQUIRED statuses. The System diagnostic
was dismissed through its UI; the original process/account closed, no new
definition leaves remained and input responded. The existing no_std memory
inspection application also exercised the actual public SDK, traps, native
account/reallocation/refusal paths, four service stacks and their eight guards.
These observations used real guest services; no host Rust suite supplied them.

The broader no_std conformance application failed with ACCESS_DENIED after
creating its System-owned crash report. Source tracing finds an ordinary Window
close of that report after the fixture explicitly expects report-dismissal
denial. This is not permission to weaken Window ownership. Its fixture call and
restriction also exist in the earlier source, but no native baseline comparison
was run. The full conformance scenario remains failed/unqualified.

Earlier collectors queried an app before its actual launch record and waited
for final exit while a crash report was intentionally undismissed. Those first
failures remain evidence; corrected collectors waited for the real record and
dismissed the actual report, without changing kernel semantics or timeouts.
An earlier artifact performed retirement under Desktop; it is superseded here,
and its observations do not qualify the corrected maintenance path. Sources and
base artifacts stayed fixed per capture; owned guests were reaped and cloned
media removed, including failed cases.

Pressure, uncertain acknowledgments, direct stale private-reference injection,
concurrent invocation/retirement races, foreign-bound Module unload and timing
remain unverified. The current classic adapter does not implement window/control
creation; no second decoder was added to guess unsupported trap arguments.
These are trusted supervisor mappings, not U-mode isolation or complete classic
application compatibility.
