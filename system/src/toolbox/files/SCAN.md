# Incremental directory enumeration

`system.files().scan_directory(volume, directory, &mut cursor)` reads at most one catalog leaf and examines at most eight candidate records. `ScanStep::Entry` includes public `CatalogInfo` and the exact catalog physical lengths of both forks. `Pending` means ordinary progress without an entry; return to the event loop before continuing. `Done` is terminal. A copied cursor copies its position, and `DirectoryCursor::default()` starts another scan. No SDK allocation is needed.

The descriptor captures resolved catalog extents and validated B-tree header geometry while the volume is already mounted. Advancing a cursor never remounts or walks the extents-overflow tree. A descriptor refresh reads the header after a mutation while its mounted `Volume` remains available. If refresh cannot construct a usable descriptor, new scans report an error rather than reuse stale geometry.

Opaque continuations bind their volume, directory and monotonic revision. Conservatively invalidating operations include folder creation, moves/Trash changes, renames, lock/stationery changes and Desktop DB comment writes. Failed write attempts may invalidate as well. Ordinary catalog/comment reads do not. A global checked atomic revision allocator also distinguishes File Manager resets/remounts. `SCAN_STALE` (-16) leaves the caller's cursor unchanged: discard partial totals and restart, with a bounded retry policy.

A scan of the `Pipes` folder is the one enumeration with two sources. It walks the catalog exactly as every other directory, then appends the resident named-pipe registry's rows once the catalog reports `Done`. The continuation carries the registry revision in `DirectoryScanCursor::reserved` and the row offset in `DirectoryScanCursor::registry`; both are zero for every ordinary directory and are rejected as `BadArgument` elsewhere. A named pipe registered or destroyed while the enumeration is open changes that revision, so the next step reports `SCAN_STALE` instead of continuing with offsets that no longer mean the same items. Anonymous pipes are not in the registry, so no scan can see them.

The resident native gate accepts a new, exact-size `FileScanCall` at File operation25. The original `FileCall`, `CatalogInfo`, and ABI6 layouts remain unchanged. The Pascal trap adapter changes only an Entry's inline name representation; cursor progress, numeric metadata and physical lengths match the native request. The Rust SDK exposes UTF8 names.

Every step validates cursor state, context, node/record limits, traversal count and backward links; leaf self-links and immediate reverse cycles are rejected. The full offset table must fit the validated leaf before any record is parsed. Chain length is bounded by the tree's node count and65,536-node profile limit. Leaf buffers use fallible allocation, with a maximum supported node size32KiB. These are work bounds, not a promise of sub-millisecond host storage latency for every leaf size or device.

`crates/mac-toolbox/tests/directory_scans.rs` exercised the public SDK on actual disposable HFS media. It compared entries and physical lengths with existing catalog APIs; counted actual sector reads to verify one512-byte fixture leaf per step; tested Pending, completion, read stability, mutation/remount staleness, cursor binding/forgery rejection, malformed leaf offset tables/cycles, and native/Pascal Unicode name conversion. It was removed with the host test suite ([testing policy](../../../../docs/TESTING-POLICY.md)), so those properties are **unverified** on the target until a `cargo xtask boot-check` case covers them.
