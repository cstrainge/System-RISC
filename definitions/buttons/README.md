# Buttons, Checkboxes and Radio Buttons CDEF

`CDEF_BUTTONS` is System resource `CDEF 0`, named **Buttons, Checkboxes and Radio Buttons**. The `native-buttons-cdef` package in `definitions/buttons` implements push buttons, checkboxes and radio buttons (procedures 0/1/2), plus their use-window-font procedures 8/9/10. Unique rendering and hit behavior live in `src/main.rs`; the resident Control Manager handles resource resolution, validation and retained replay.

Original System 7.6.1 CDEF 0 is 1,350 bytes, SHA256 `b647566a3fe540ae1e2477e6c3ced3d3a33cfffc131fcd8fbfa22c5774cc0dde`. Its disassembly and captured states are under `working/control-tracking-reference` and `results/control-tracking-reference`. The reconstruction follows the original variation mask, rounded-button corner size, 12×12 checkbox/radio geometry, odd-value mark test, full-rectangle hit test, and multiline title baseline formula. The bounded radio masks encode glyph geometry only; buttons, captions and placement remain dynamic.

All new compatibility assertions live in `crates/mac-toolbox/tests/conformance/controls.rs`, imported by the host suite and RV64 ECALL launcher. The tests use public aggregate SDKs and the real resident adapters/CDEF implementations. Independent captured pixels are encoded in `tests/data/original-control-pixels.bin`: 54 whole control rectangles, 155,520 pixels, no masks. The same suite covers 32 original scrollbar states (114,080 pixels) and 8,424 original hit records (1,296 distinct tuples; repeated original capture passes retained). `tests/data/capture_controls.py` packages original captures without invoking native rendering.

The exact claim is bounded to those captured sizes, text and states. use-window-font currently supports Chicago 12 and Geneva 9. Other selected fonts return `NOT_SUPPORTED`; arbitrary font support needs the resident font-query path on the definition surface. Color overrides, custom control definitions and reserved standard procedures are not covered. Native definition messages are explicit adapters, not the original Pascal CDEF calling convention.

The lifecycle/tracking manager is a following slice. Existing APIs draw explicit snapshots. They do not implement original synchronous `TrackControl`, action callbacks, per-control handles, or automatic press/leave/reenter/cancel animation. Checkbox/radio values must be changed by the application; original tracking does not toggle them. In particular, an original thumb drag preserves the old thumb until release and draws a patterned XOR outline; the current stateless value-from-point helper is not that tracking contract. See `tests/data/control-scope-ledger.json`.
